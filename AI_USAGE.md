# AI usage declaration

*Pakistan Glacier Intelligence Explorer — NASA Space Apps Challenge 2026, “Dancing with the SARs”.*

In line with the NASA Space Apps rules, our team declares that **generative AI tools were used extensively in this
project**. This file describes which tools, what they did, and what the team did. The same declaration appears in the
README, in the header of every source file, in the notebooks' metadata, in the web app's methodology panel, in the
exported app data (`app/data/manifest.json` → `provenance`) and in the team handbook.

## Tools used

| Tool | Provider | How we used it |
|---|---|---|
| **Claude** (Claude Opus 5.5, used through **Claude Code**, an AI coding assistant) | Anthropic | Main development assistant: wrote and ran the code, processed the data, built the web app, wrote the documentation |
| **ChatGPT** | OpenAI | Early planning only: explaining the 2026 challenges, comparing project ideas, suggesting data sources (NISAR GOFF, ITS_LIVE) and a first project roadmap; it also produced a conceptual UI mock-up image that is **not** included in this project |

## What the AI did

**Claude (via Claude Code)**
- **Code — AI-generated:** the processing library (`src/pgie/`), all four notebooks (`notebooks/`), the scripts
  (`scripts/`), the automated test (`tests/test_inversion.py`) and the entire web application (`app/`).
- **Data processing — AI-executed:** inspected the downloaded NISAR and ITS_LIVE files, ran the processing, produced
  every derived dataset, table and figure in `processed/`, `results/` and `app/data/`.
- **Method design — AI-proposed, team-approved:** e.g. stable-rock calibration, the ascending + descending velocity
  inversion, the significance test, hotspot detection and the centreline. Choices were explained and agreed with the team.
- **Checking — AI-performed:** validation against ITS_LIVE, a synthetic test of the velocity maths, browser tests of the
  app (screenshots captured with an automated headless browser), responsive-layout checks.
- **Writing — AI-drafted:** the README, this file, the in-app text and methodology panel, and the team handbook
  (`docs/*.docx`, generated by `scripts/build_report.py`).
- **Publishing — AI-performed with team login:** created the git repository, pushed it to GitHub and set up GitHub Pages.

**ChatGPT** — brainstorming and planning before development started (see table above).

## What the team did
- Chose the challenge, the region (Pakistan) and the target (Siachen Glacier), and set the project's goals.
- Downloaded the satellite data from NASA sources (ASF Vertex for NISAR GOFF, the ITS_LIVE portal) onto our computer.
- Directed the work step by step: requested features, gave design feedback (e.g. full-screen map, fly-in intro,
  removable widgets, 3-D view), set safeguards (no simulated vertical motion, 3-D off by default) and made the final decisions.
- Reviewed the results, the app and the documents, and wrote the problem → solution framing used in the README.
- Owns the project and is responsible for its content.

## Images, audio and branding
- **No AI-generated images are included.** All figures are plots drawn by code from the satellite data; all app
  screenshots are captures of the real application. (If any AI-generated image is added later, it will carry a visible
  “AI-generated” watermark.)
- **No AI-generated audio** is used.
- **No NASA logos, flags or design elements** appear in the app, figures or documents; NASA, NISAR and ITS_LIVE are
  named only as text credits for the data.

## Data
The scientific inputs are unmodified NASA open data (NISAR L2 GOFF, DOI 10.5067/NIL2GOFF-B1; ITS_LIVE v2.1).
**All derived data products in this repository were produced by AI-written code** and are labelled as such in their
metadata (`app/data/manifest.json` → `provenance`).
